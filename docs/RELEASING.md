# Releasing

How a release is built, checked and published. AutoClicker ships as a DMG on [GitHub Releases](https://github.com/mfatihkara8/AutoClicker/releases). It is signed with an Apple Development certificate and is not notarized ([ADR-010](DECISIONS.md#adr-010-releases-signed-with-an-apple-development-certificate-not-notarized)).

## Checklist
1. **Version:**
   - Set `MARKETING_VERSION` to the new version in every build configuration of `AutoClicker.xcodeproj`.
   - Raise `CURRENT_PROJECT_VERSION` by one.
2. **Checks:** the build, unit tests and strict lint pass. The commands are in [CLAUDE.md](../CLAUDE.md).
3. **Performance:** if the engine or the window changed, re-check SC-6 and SC-11 with [the measurement steps](#measuring-performance).
4. **Changelog:**
   - In [CHANGELOG.md](../CHANGELOG.md), rename `[Unreleased]` to `[x.y.z] - YYYY-MM-DD` and start a new, empty `[Unreleased]` above it.
   - Update the compare links at the bottom.
5. **Build:** run `scripts/build-release.sh` and note the SHA-256 it prints.
6. **Check the DMG:** mount it read-only and confirm three things:
   - the app shows the new version,
   - its signature verifies,
   - it carries no `get-task-allow` entitlement.

   ```sh
   mnt=$(mktemp -d)
   hdiutil attach -readonly -nobrowse -mountpoint "$mnt" build/Release/AutoClicker-x.y.z.dmg
   /usr/libexec/PlistBuddy -c 'Print :CFBundleShortVersionString' "$mnt/AutoClicker.app/Contents/Info.plist"
   codesign --verify --deep --strict "$mnt/AutoClicker.app" && codesign -d --entitlements - "$mnt/AutoClicker.app"
   hdiutil detach "$mnt"
   ```

7. **Tag:** commit, create an annotated tag `vx.y.z`, and push `main` and the tag.
8. **Publish:**

   ```sh
   gh release create vx.y.z build/Release/AutoClicker-x.y.z.dmg --title "AutoClicker x.y.z" --notes-file notes.md --verify-tag
   ```

   The notes should include:
   - the highlights,
   - the install and first launch steps from the README,
   - the DMG's SHA-256,
   - known limitations.
9. **First launch:** download the DMG from the release page, so that macOS quarantines it. Then follow the README's install steps on the newest macOS.

## Release build
`scripts/build-release.sh` builds the Release configuration and packages it:

```sh
# Signed, verified build, packaged as build/Release/AutoClicker-<version>.dmg
scripts/build-release.sh

# The same build for leaks and Instruments, with no DMG
scripts/build-release.sh --profiling
```

The release build:
- **Architecture and signing:**
  - It is universal (Apple Silicon and Intel).
  - It is signed with the team's **Apple Development** certificate, with the Hardened Runtime and a secure timestamp. Your keychain needs that certificate.
  - It is never ad-hoc signed, because that would reset users' Accessibility permission on every update.
- **No debugger access:**
  - It leaves out the `get-task-allow` entitlement, so no debugger can attach to the shipped app.
  - It also turns off code coverage, which Xcode's autogenerated scheme would otherwise compile into the binary.
- **Gatekeeper:** the script verifies the signature and prints the Gatekeeper assessment. Gatekeeper rejects the app until it is notarized, so the script shows that result but does not stop on it.
- **Output:** `build/Release/AutoClicker-<version>.dmg`, holding the app and a link to Applications.
  - The version is `MARKETING_VERSION`.
  - The DMG is signed with the same certificate.
  - The script prints the DMG's SHA-256.

`--profiling` keeps `get-task-allow`, so `leaks` and Instruments can attach. It writes to `build/Release/Profiling` and prints the app's path. Never ship this build.

Any `NAME=value` argument is passed to `xcodebuild` as a build setting.

The signing certificate's name is part of the app's designated requirement, which macOS uses to recognize the app. A renewed certificate with the same name keeps users' Accessibility permission. A different certificate makes them grant it again.

## Measuring performance
SC-6 and SC-11 ([GOALS.md](GOALS.md)) are measured on the profiling build while someone drives the app:

1. Build and open the profiling build:

   ```sh
   scripts/build-release.sh --profiling
   open build/Release/Profiling/DerivedData/Build/Products/Release/AutoClicker.app
   ```

2. Set a 10 ms interval, a fixed target on an empty part of the desktop, and **After duration → 60 s**.
3. Start the measurement:

   ```sh
   scripts/measure-performance.sh 240 --trace
   ```

   It samples the app's CPU and memory once a second. With `--trace` it also records a Time Profiler trace.
4. While it runs:
   - wait about 20 s, so the idle CPU is measured,
   - press the shortcut and let the 60 s run finish,
   - start and stop about 10 times.
5. Read the summary:
   - the click count should be within 2% of 6,000,
   - CPU while clicking should stay below 5%,
   - CPU while idle should be about 0%,
   - memory should stay flat,
   - `leaks` should report 0 leaks.

   The CSV, the trace and the `leaks` report are written to `build/profiling/`.
6. Quit the app and unregister the profiling build from LaunchServices with the `lsregister -u` command that the build script prints.

## Notarization
Notarization requires a paid Apple Developer Program membership. It removes the first-launch warning. With a membership:

1. Create a **Developer ID Application** certificate: *Xcode → Settings → Accounts → Manage Certificates → + → Developer ID Application*.
2. Build with it. The script signs the DMG with the same certificate as the app:

   ```sh
   scripts/build-release.sh CODE_SIGN_STYLE=Manual CODE_SIGN_IDENTITY="Developer ID Application"
   ```

3. Store the notary credentials in your keychain, once. The command asks for an app-specific password, which you create at [account.apple.com](https://account.apple.com):

   ```sh
   xcrun notarytool store-credentials AutoClicker-notary --apple-id <your-apple-id> --team-id 9J8JPZCUTL
   ```

4. Submit the DMG and wait for the result:

   ```sh
   xcrun notarytool submit build/Release/AutoClicker-<version>.dmg --keychain-profile AutoClicker-notary --wait
   ```

   If it is rejected, `xcrun notarytool log <submission-id> --keychain-profile AutoClicker-notary` explains why.

5. Staple the ticket to the DMG, so Gatekeeper can check it offline:

   ```sh
   xcrun stapler staple build/Release/AutoClicker-<version>.dmg
   ```

6. Check the result:

   ```sh
   xcrun stapler validate build/Release/AutoClicker-<version>.dmg
   spctl -a -t open --context context:primary-signature -vv build/Release/AutoClicker-<version>.dmg
   ```

   `spctl` should print `accepted` and `source=Notarized Developer ID`.

Stapling changes the DMG, so take its SHA-256 afterwards. A Developer ID certificate also changes the app's signature, so users of an earlier build have to grant Accessibility again. Moving to Developer ID needs a new ADR that supersedes ADR-010.
